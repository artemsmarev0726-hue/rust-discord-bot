# Rust Discord Bot 1.1

Бот ставится на хостинг **вне РФ**. Игровой сервер в Discord сам больше не ходит: всё идёт через бота по обычному HTTP.

```
Rust-сервер (РФ) ──HTTP──▶ бот (хостинг вне РФ) ──▶ Discord
                 ◀──HTTP── (сервер сам забирает команды у бота)
```

Что умеет:

1. **Статус бота** — «👥 Участников: N | 🟢 Онлайн: M», можно добавить онлайн Rust-сервера.
2. **Стримы Twitch** — начало и конец стрима (с длительностью) в канал.
3. **Наигранное время** — `/статистика`, `/статистика-сброс`.
4. **Ретранслятор вебхуков** — логи всех плагинов (Chat, YnaziCotTvBridge, DiscordPresenceDynamic, RaidTournament…) идут через бота. Бот копит их на диске и доставляет в Discord с повторами. Плагины менять не нужно, только адрес вебхука.
5. **Команды из Discord на сервер** — `/консоль команда: kick Ник` (для админов, список разрешённых команд в конфиге).

## 0. Деплой через GitHub (bothost)

Это **отдельный бот**, рядом с QUICK RUST, со своим репозиторием и слотом на хостинге.

1. Создай **новое приложение** в Discord Developer Portal (свой токен). Токен QUICK RUST не используй: боты затрут слэш-команды друг друга.
2. Создай новый репозиторий на GitHub (лучше **приватный**) и залей в него содержимое этой папки (`package.json`, `Dockerfile`, `src/` и т.д. — в корне репозитория).
3. **Токен и секреты в репозиторий не коммить.** В `config.json` оставь заглушки, реальные значения задай во вкладке «Переменные» на bothost:
   `DISCORD_TOKEN`, `GUILD_ID`, `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`, `API_SECRET`, `RELAY_SECRET`.
   Несекретное (ID каналов, стримеры, тексты) — прямо в `config.json` в репозитории.
4. На bothost создай новый бот из этого репозитория (язык Node.js / Dockerfile), во вкладке «Домен» включи домен и порт `3000`.
5. В QUICK RUST выключи Twitch (`"twitch": { "enabled": false }` в его config.json + `/config_reload`), иначе уведомления о стримах придут дважды.
6. Папка `data/` (статистика, очередь вебхуков) не в Git. Если на хостинге есть постоянный диск — укажи путь к нему в переменной `DATA_DIR`; иначе перед передеплоем сохраняй `data/` через «Бэкапы».

## 1. Discord

1. <https://discord.com/developers/applications> → New Application → **Bot** → Reset Token → в `token`.
2. Привилегированные интенты **не нужны**.
3. OAuth2 → URL Generator: scopes `bot` + `applications.commands`; права: View Channels, Send Messages, Embed Links, Attach Files, Read Message History, Mention Everyone (для `@everyone` при старте стрима).
4. Режим разработчика → ПКМ по серверу → «Копировать ID» → `guildId`; ПКМ по каналу стримов → `twitch.notifyChannelId`.

## 2. Twitch

<https://dev.twitch.tv/console/apps> → Register Your Application (Redirect URL `http://localhost`) → **Client ID** и **New Secret** → `twitch.clientId` / `twitch.clientSecret`.

```json
"streamers": [ { "url": "https://www.twitch.tv/nickname", "steamId": "76561198xxxxxxxxx" } ]
```

`steamId` нужен, чтобы в `/статистика` у игрока была ссылка на его Twitch (можно оставить пустым).

## 3. Хостинг бота

Node.js **18.17+**, открытый входящий порт (`http.port`, по умолчанию `8080`).

```bash
npm install
npm start
```

- Хостинг выдаёт порт через переменную `PORT` → бот возьмёт её сам.
- Секреты можно задать переменными окружения: `DISCORD_TOKEN`, `GUILD_ID`, `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET`, `API_SECRET`, `RELAY_SECRET`.
- Проверка: `http://IP_БОТА:8080/api/health` → `{"ok":true}`.
- **Проверь с игрового сервера**, что бот доступен: `curl http://IP_БОТА:8080/api/health`. Некоторые зарубежные хостинги в РФ режутся — тогда выбери другой.
- Данные — в папке `data/` (статистика, стримы, очередь вебхуков). При переносе копировать её.
- VPS: `npm i -g pm2 && pm2 start src/index.js --name rustbot && pm2 save && pm2 startup`.

## 4. Плагин `DiscordBotLink.cs`

`plugin/DiscordBotLink.cs` → `oxide/plugins/`. В `oxide/config/DiscordBotLink.json`:

| Параметр | Значение |
|---|---|
| Адрес бота | `http://IP_БОТА:8080` |
| Секрет | как `api.secret` в конфиге бота |
| Отправлять онлайн сервера боту | `true` — для `{server_online}` в статусе бота |
| Выполнять консольные команды из Discord | `true` — для `/консоль` |
| Учитывать только эти SteamID | пусто = всех игроков |

Консоль: `botlink.status`, `botlink.flush`.

Плагин сам опрашивает бота раз в 3 с, есть ли команды. Поэтому на игровом сервере не нужно открывать порты, и Discord ему не нужен.

## 5. Ретранслятор вебхуков (логи плагинов)

В конфиге бота задай `relay.secret`, а в конфигах плагинов замени начало адреса вебхука:

```
было:  https://discord.com/api/webhooks/123456/AbCdEf...
стало: http://IP_БОТА:8080/<relay.secret>/api/webhooks/123456/AbCdEf...
```

Как это работает:

- Бот сразу отвечает плагину `204`, поэтому для плагина сообщение «доставлено».
- Сообщение записывается в `data/relay-queue.json` (переживёт перезапуск бота) и уходит в Discord.
- Порядок сообщений внутри каждого вебхука сохраняется. Лимиты Discord (429) соблюдаются.
- При ошибках связи повтор идёт через 2 с → 4 → 8 … до 5 мин.
- Если Discord вернул 400/404 (битое сообщение, удалённый вебхук), сообщение выбрасывается, в лог бота пишется причина.
- Запросы с `?wait=true` и GET передаются напрямую, и плагин получает ответ Discord как есть.
- `relay.allowedIps` — впиши IP игрового сервера, тогда чужие не смогут слать через бота. Ещё можно ограничить список вебхуков: `relay.allowedWebhookIds`.
- Состояние очереди: `http://IP_БОТА:8080/<relay.secret>/relay-status`.

Очереди повторов в самих плагинах (Chat, YnaziCotTvBridge, DiscordPresenceDynamic) можно оставить: они сработают, если недоступен сам бот.

## 6. Статус бота

`presence.text`, плейсхолдеры:

- `{members}`, `{online}` — участники Discord / в сети;
- `{server_online}`, `{server_max}`, `{server_queue}`, `{server_joining}` — Rust-сервер (присылает плагин; если данных нет 3 мин — `serverOfflineText`).

Пример: `"🎮 {server_online}/{server_max} | 👥 {members}"`. Максимум 128 символов.

## 7. Команды

| Команда | Кто | Что |
|---|---|---|
| `/статистика` | все | наигранное время + время стримов, полный список файлом CSV |
| `/статистика-сброс` | админы / `adminRoleIds` | обнулить (с подтверждением, итоги — файлом, копия в `data/backups/`) |
| `/консоль команда:…` | админы / `adminRoleIds` | выполнить консольную команду на сервере и показать вывод |

`console.allowedCommands` — разрешённые команды (первое слово). Пустой список = любые команды, в том числе `quit`, так что лучше не оставлять пустым. Команда, которую сервер не забрал за 30 с, отменяется, чтобы не выполниться неожиданно позже.

Примечание: связь идёт по HTTP, секреты передаются открытым текстом. Если у хостинга есть домен с HTTPS, используй `https://…`.
